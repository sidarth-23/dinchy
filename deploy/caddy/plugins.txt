# Caddy plugins compiled into this installation's Caddy binary.
#
# One entry per line as module@version; blank lines and # comments are ignored.
# The version is REQUIRED: xcaddy has no lockfile, so an unpinned entry silently
# produces a different binary on every build. `mise run caddy:build` rejects a line
# without a version rather than resolving it for you.
#
# After editing, rebuild and restart Caddy:
#
#     mise run caddy:build           # local development, writes tmp/caddy
#     sudo systemctl restart caddy   # production, after installing the new binary
#
# The restart is safe: Caddy runs with --resume and restores the routes Dinchy pushed,
# so no configuration is lost and Dinchy does not need to be running.
#
# Find plugins at https://caddyserver.com/download — every module listed there can go
# here. The most common homelab addition is a DNS provider, which lets Caddy answer
# ACME DNS-01 challenges and so issue certificates for a host behind NAT with no
# inbound port 80:
#
#github.com/caddy-dns/cloudflare@v0.2.1
#
# Dinchy reads the compiled-in module list from the binary, so a route that asks for a
# provider you have not added here is rejected with a message naming it, instead of
# failing later during certificate issuance.

# The Caddy version itself is pinned here so the whole build is reproducible. Keep it in
# step with the aqua:caddyserver/caddy pin in mise.toml, so a plugin build and the
# vanilla development binary are the same Caddy.
caddy@v2.11.4
